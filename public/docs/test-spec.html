SFA テスト仕様書

中小企業向け営業支援ツール「SFA」の受け入れテスト仕様。Web からの申し込みとテナントの自動作成、課金のルール、利用開始までの流れ、各機能の動作を、テスターが順に確認できるようにまとめています。各項目の右にある OK / NG / 保留 を押すと結果がこのブラウザに保存され、上部の集計に反映されます。v1.1 では、パスワード再設定、法務ページ、Gmail 以外のメールサーバー、担当者・取引先の付け替えと統合、フォーム通知の項目名設定の項目(ID の末尾が 07 以降と MS-04〜06)を追加しました。v1.4 では、行動の種類の設定(DL-06)、期限・日時の入力部品(DL-07)、タグの並び替え(MS-03)を追加し、DL-05 を新しい期限入力に合わせて修正しました。

§0テスト環境と準備

テストは本番 URL https://sfa.art-trading.net で行います(Stripe はテストモードのため実際の請求は発生しません)。画面の指示にあるパス(/signup など)はこの URL の配下です。以下をそろえてから開始してください。

テスト用メール
申し込み用に、まだこのシステムに登録されていないメールアドレスを 2 つ(会社 A 用・会社 B 用)。自社ドメインのエイリアス(name+testa@…)で可。
Gmail 連携用
受信テスト用の Gmail アカウントとアプリパスワード(myaccount.google.com/apppasswords)。
Stripe テストカード
成功: 4242 4242 4242 4242 / 拒否: 4000 0000 0000 0002 / 有効期限は未来の任意、CVC 任意、郵便番号任意。
運営アカウント
運営管理 https://sfa.art-trading.net/admin にログインできるスーパーユーザー(akfujii@art-trading.co.jp)。
Stripe ダッシュボード
テストモードで顧客・サブスクリプション・Webhook の配信状況を確認できること。
結果の判定基準: 期待結果がすべて満たされれば OK。ひとつでも違えば NG にし、メモ欄に画面のメッセージをそのまま書いてください。環境の都合で実施できない場合は保留。
お試し期限切れの再現: お試し期間は 90 日なので、期限切れの動作は運営管理 → テナント詳細 → 契約・上限・課金状態の「お試し期限」を過去の日付に変えて再現します(テスト後に戻すこと)。

§1申し込みとテナント自動作成

Web の申し込みフォームから、運営の手を介さずに会社(テナント)が作られるまで。カードの登録は不要で、90 日間のお試しが自動で始まります。

https://sfa.art-trading.net/signup申し込みフォーム会社名・会社 ID・担当者・メール
mail確認メール運営側 Gmail から 24 時間有効のリンク
/signup/verify内容確認「アカウントを開設する」ボタン
create_tenantテナント作成お試し 90 日、上限は運営の既定値
/set-passwordパスワード設定そのままログイン状態に

入力ルール

項目ルール
会社 ID英小文字・数字・ハイフン、3〜40 文字、先頭と末尾は英数字。会社名からの自動提案あり。既存テナントと重複不可。後から変更不可。
メールアドレス既にログインできる利用者のアドレスは不可(別テナントに所属しているため)。
連投の抑制同じメールアドレスは 24 時間に 3 回まで。同じ IP は 1 時間に 10 回まで。
確認リンク有効期限 24 時間。1 回使うと無効。リンクを開いただけではテナントは作られない(ボタンを押した時点で作成)。

§2利用開始

開設直後の会社が、メールアカウントを連携してメールを取り込み、同僚を招待するまで。ログインは招待制で、自己登録はできません。パスワードを忘れたときは再設定メールで復旧します。

ON-01
必須
ログインとログアウト
手順
  1. ログアウトし、SU-02 のメールとパスワードでログイン
  2. 間違ったパスワードでログイン
  3. ログイン状態で /login を直接開く
期待結果
  • 正しい認証情報でダッシュボードが開き、ヘッダーに会社名が出る
  • 誤りはエラーメッセージが出て入力画面に留まる
  • ログイン中に /login を開くとダッシュボードへ戻される
ON-02
必須
未ログインでは業務画面を開けない
手順
  1. ログアウトした状態で /inbox、/deals、/settings/billing を直接開く
期待結果
  • いずれもログイン画面へリダイレクトされ、ログイン後に元のページへ戻る
ON-03
必須
Gmail アカウントの連携と初回同期
前提テスト用 Gmail とアプリパスワード。受信トレイに数通のメールがあること。
手順
  1. 設定 → 「メールアカウントを追加」で「Gmail / Google Workspace」を選び、メールアドレスとアプリパスワードを登録
  2. 接続テストを実行
  3. 「今すぐ同期」を押す
  4. メール一覧を開く
期待結果
  • 接続テストが成功し、「既定の差出人」バッジと「Gmail / Google Workspace」の表示が付く
  • 同期後に最終同期日時が表示され、受信メールと送信済みメールが一覧に入る
  • 差出人が担当者・取引先として自動登録される(担当者一覧で確認)
  • 誤ったアプリパスワードでは接続テストが失敗し、原因が分かるメッセージが出る
ON-04
必須
同僚を招待してログインできるようにする
前提運営管理でこの会社のユーザー上限を 2 に上げておく(既定は 1 で招待不可)。
手順
  1. 営業担当者 → 追加でメールアドレス付きの担当者を作る
  2. 「招待」を押す
  3. 届いた招待メールのリンクからパスワードを設定
  4. 別ブラウザでその人としてログイン
期待結果
  • 招待メールは自社(会社 A)の Gmail から送られ、招待者名が入っている
  • 担当者の状態が「招待中」→ ログイン後に「ログイン可」に変わる
  • 営業担当者ページの「N / 上限」が 2 / 2 になる
  • その人は同じ会社のデータだけが見える
ON-05
通常
ユーザー上限に達すると招待できない
手順
  1. ON-04 の状態(2 / 2)でさらに担当者を追加して「招待」
  2. 招待済みの担当者に「再送」
期待結果
  • 新規招待は「ログインユーザー数の上限(2 名、招待中を含む)に達しています」で止まる
  • 再送は枠を消費せず送れる
ON-07
必須
パスワードの再設定
前提SU-02 のアカウント(会社 A)でログアウト済み。
手順
  1. ログイン画面の「パスワードを忘れた方」を開き、SU-02 のメールアドレスを送信
  2. 未登録のアドレスでも送信
  3. 届いたメールのリンクを開き、新しいパスワードを設定
  4. 古いパスワードと新しいパスワードでそれぞれログイン
  5. 使用済みのリンクをもう一度開く
期待結果
  • 登録あり・なしのどちらも「登録されていれば再設定メールを送りました」の同じ文言になる(登録の有無が分からない)
  • 【SFA】パスワード再設定のご案内 が会社 A の既定メールアカウント(無ければ運営側)から届く
  • リンク先は「新しいパスワードを設定」の画面で、設定後にダッシュボードが開く
  • 古いパスワードは拒否され、新しいパスワードでログインできる
  • 使用済みリンクは「パスワード再設定のリンクが無効か、有効期限が切れています」のログイン画面になる
  • 同じアドレスに 4 回続けて送ると、4 回目はメールが届かない(画面の文言は同じ)
ON-08
必須
Gmail 以外の IMAP / SMTP サーバーの連携
前提レンタルサーバーなど、IMAP と SMTP が使えるメールアカウントとその設定値。メールアカウント上限 2 以上。
手順
  1. 「メールアカウントを追加」で「その他の IMAP / SMTP サーバー」を選ぶ
  2. IMAP サーバー:993、SMTP サーバー:465(または 587)、必要ならログイン ID を入力して保存
  3. 接続テスト → 今すぐ同期
  4. そのアカウントを差出人にしてメールを送信
  5. SMTP ポートを 25 や暗号化なしの設定にして接続テスト
  6. サーバー名に URL(https://…)を入れて保存
期待結果
  • 設定一覧に「その他の IMAP / SMTP サーバー · IMAP ホスト:ポート / SMTP ホスト:ポート」とログイン ID が表示される
  • 接続テストが成功し、受信トレイと送信済み(Sent / Sent Items / 送信済み などの名前でも)が取り込まれる
  • 587 は STARTTLS で送信できる。暗号化に対応しないポートは接続テストが失敗し、原因の分かるメッセージが出る
  • URL 形式のサーバー名は「ホスト名だけを入力してください」で保存できない
ON-06
通常
営業担当者の削除でログインが無効になり枠が空く
手順
  1. ON-04 で招待した人を削除
  2. その人のブラウザで画面を操作
  3. 自分自身を削除しようとする
期待結果
  • 削除後、その人は次の操作でログイン画面に戻され、再ログインできない
  • 「N / 上限」が 1 / 2 に戻る
  • 自分自身は「削除できません」のメッセージ

§3課金のルール

料金は上限ではなく実際の利用数で毎月計算し、Stripe のサブスクリプション数量に自動で反映します。お試し中はカード不要、期限が切れると閲覧のみになります。

料金の計算

基本料金にメールアカウント 1 件・ユーザー 1 名(招待中を含む)・容量 1GB が含まれ、超えた分がオプション料金になります。消費税 10% は外税で、円未満は切り捨てです。

項目単価(税抜)数え方
基本料金10,000 円/月常に 1
ユーザー追加1,000 円/名ログインできる利用者 + 招待中 − 1
メールアカウント追加5,000 円/件連携メールアカウント数 − 1
容量追加0 円/GB使用容量を GB に切り上げ − 1(単価 0 のため Stripe には載らない)
検算例: ユーザー 3 名、メールアカウント 2 件 → 10,000 + 2 × 1,000 + 1 × 5,000 = 17,000 円、消費税 1,700 円、税込 18,700 円。

契約状態の遷移

Stripe からの Webhook で、テナントの契約状態と課金状態が自動更新されます。

Stripe の状態契約状態課金状態利用
(未登録)お試し期間お試し中期限内は利用可、期限後は閲覧のみ
trialingお試し期間お試し中利用可(カード登録済み、期限は Stripe と同期)
active契約中課金中利用可
past_due契約中支払い遅延利用可(警告表示、Stripe が再試行)
unpaid / paused停止中支払い遅延閲覧のみ
canceled解約解約済み閲覧のみ、「再開する」ボタン
運営が手で「停止中」にしたテナントは、Stripe の状態で上書きされません(運営の停止が優先)。
BL-01
必須
ご契約・お支払い画面の料金内訳
前提会社 A: ユーザー 2 名(招待中を含む)、メールアカウント 1 件。
手順
  1. 設定 → 「ご契約・お支払い」を開く
  2. Gmail アカウントをもう 1 件追加して再表示
期待結果

  • メールアカウント追加後は 5,000 円増え、小計 16,000、税込 17,600 円
  • お試しの残り日数と期限、ご利用状況(N / 上限)が表示される
BL-02
必須
お試し中にカードを登録すると、課金開始がお試し終了日になる
前提お試し残り 2 日以上。Stripe テストモード。
手順
  1. 「お支払い方法を登録して契約する」を押す
  2. Stripe Checkout で 4242… のカードを入力して登録
  3. 戻った画面と Stripe ダッシュボードを確認
期待結果
  • Checkout は日本語表示で、明細に基本料金と追加分、消費税 10% が載る
  • 戻ると「お支払い方法を登録しました」と出て、契約状態は「お試し期間」のまま、「お支払い方法は登録済み。お試し終了後に自動課金」の説明になる
  • Stripe のサブスクリプションが trialing で、トライアル終了日がテナントのお試し期限と一致
  • 顧客のメタデータに tenant_id と会社 ID が入っている
  • 「お支払い方法・請求書を管理」ボタンが表示される
BL-03
必須
お試し期限切れで閲覧のみになり、カード登録で復帰する
前提会社 B(カード未登録)。運営管理でお試し期限を昨日に変更。
手順
  1. 会社 B でログインして各画面を開く
  2. 取引先の追加、メール送信、同期を試す
  3. バナーのリンクから「ご契約・お支払い」→ カード登録
期待結果
  • 上部に「お試し期間が終了しました…閲覧のみ」のバナーとご契約・お支払いへのリンク。ご契約・お支払い画面には「登録がない場合、利用規約にもとづきデータは削除されます」の案内
  • 書き込み操作はすべて「お試し期間が終了しました」のエラーで止まる。閲覧はできる
  • カード登録後は即時課金され、契約状態が「契約中」、課金状態が「課金中」になり、バナーが消えて操作できる
  • 次回請求日が表示される
BL-04
通常
お試し終了 7 日前からの案内バナー
前提カード未登録の会社。運営管理でお試し期限を 5 日後に変更。
手順
  1. その会社でログイン
  2. カードを登録して再表示
期待結果
  • 「お試し期間はあと 5 日で終了します」の青いバナーとリンクが出る
  • カード登録後はバナーが消える
BL-05
必須
利用数の変化が Stripe の数量に自動反映される
前提契約中(または trialing)の会社。ユーザー上限 3、メールアカウント上限 2。

  2. Gmail アカウントを追加する
  3. Stripe ダッシュボードでサブスクリプションの明細を確認
  4. 招待した担当者を削除、Gmail アカウントを削除して再確認
期待結果
  • 招待後に「ユーザー追加」の数量が 1 増え、アカウント追加後に「メールアカウント追加」の明細が数量 1 で加わる(反映は数秒〜1 分)

  • 失敗した場合は設定 → システムログに stripe.sync のエラーが残る

  3. 請求書一覧を開く

期待結果

  • ポータルで解約を取り消すと注意が消える
BL-07
通常
支払い失敗時の表示と通知
前提Stripe ダッシュボード(テスト)で、対象サブスクリプションの支払い方法を「請求が失敗するカード(4000 0000 0000 0341)」に変えるか、テストクロックで請求を進める。

BL-08

§4メール

連携したメールアカウントから取り込んだメールの閲覧、返信・新規作成、問い合わせ登録、タグ付け、担当者・取引先の付け替え。返信は受信したアカウントから送られます。

MB-01
必須
受信トレイの表示と既読管理
手順
  1. メール一覧で未読メールを確認
  2. 1 通開いてスレッドを表示
  3. 一覧に戻る
期待結果
  • 未読は太字とドットで区別され、サイドメニューの「メール」に未読数バッジが出る
  • 開くと既読になりバッジが減る
  • スレッドは日時順に並び、自分の送信メールは区別して表示される
  • 日時は日本時間
MB-02
通常
検索(送信者・件名・本文)と未読絞り込み
手順
  1. 検索対象を「件名」にして既知の語で検索ボタン
  2. 「本文」「送信者」でも同様に
  3. 「未読」フィルタを切り替える
期待結果
  • 対象に応じて一致するメールだけが残る
  • 該当なしの場合は空の案内が出る
MB-03
必須
返信(署名・件名・差出人アカウント)
前提設定 → 署名に会社名などを入れておく。
手順
  1. 受信メールを開いて返信フォームを表示
  2. 本文に署名が初期表示されることを確認し、送信
  3. 相手側の受信と、スレッドへの追加を確認
期待結果
  • 署名は「会社名・担当者名・メールアドレス・追記」の順で入り、担当者名はログイン中の営業担当者名
  • 送信後にスレッドに自分の返信が付き、Gmail の送信済みにも残る
  • 差出人は受信したアカウント
MB-04
必須
新規作成と添付ファイル(ドラッグ&ドロップ)
手順
  1. 「新規作成」で宛先を複数(カンマ区切り)入力
  2. ファイルを選択で 1 件、ドラッグ&ドロップで 1 件添付
  3. 送信し、受信側で添付を確認
期待結果
  • 添付欄に 2 件表示され、削除もできる
  • 受信側に添付付きで届く
  • 送信したメールが一覧に「送信」として残り、添付をダウンロードできる
MB-05
通常
受信添付の保存と容量上限
前提運営管理でこの会社の容量上限を小さく(例: 0.01GB)して、大きめの添付を送る。
手順
  1. テスト Gmail 宛に添付付きメールを送り、同期
  2. 設定 → 会社(テナント)の使用容量を確認
期待結果
  • 上限内なら添付が一覧に表示されダウンロードできる
  • 上限を超える添付は保存されず、システムログに容量超過が記録される(メール本文は取り込まれる)
  • テスト後に上限を戻す
MB-06
通常
自社サイトのフォーム通知メールの扱い(推奨フォーマット)
前提設定 → 「問い合わせフォームの通知メール」の推奨フォーマット(会社名: / お名前: / メールアドレス: / 電話番号: / お問い合わせ内容:)で書いた本文を、フォームツール役の別アドレスから連携アカウント宛に送る。
手順
  1. フォーム通知メールを同期
  2. 担当者一覧と、そのメールの返信フォームを確認
期待結果
  • 送信元ではなく本文の問い合わせ者(会社名・氏名・メール・電話)が担当者・取引先として登録される
  • 返信の宛先が問い合わせ者になり、件名が設定の「返信件名」になる
  • 問い合わせに登録すると、要約と分類(見積依頼など)が本文の内容から付く
MB-07
通常
選択してタグ付け・一括削除
手順
  1. メールを 2 通選択して「タグ」から「リード」を付ける
  2. スレッド内の他のメールと、紐付く担当者のタグを確認
  3. タグで検索し、選択して削除(確認ダイアログ)
期待結果
  • タグはスレッド内の全メールと担当者にも付く
  • 削除はスレッド単位で消え、件数がトーストに出る
  • 削除したメールは次回同期で再取り込みされない
MB-09
必須
スレッドの担当者・取引先の付け替え
前提担当者・取引先が付いたスレッドが 2 つ以上あり、そのうち 1 つは問い合わせ登録済みで、別の取引先の案件に紐付いている。
手順
  1. スレッド画面の「担当者・取引先を変更」→「登録済みの担当者を選ぶ」で別の会社の担当者を検索して選び、変更
  2. 問い合わせページと、元の案件の「メール履歴」を確認
  3. 同じダイアログで「新しい担当者を登録する」→ 氏名・メール・「新しい取引先を登録する」で会社名を入れて変更
  4. 既存担当者と同じメールアドレスで「新しい担当者を登録する」
  5. 「取引先だけを指定する」と「紐付けを外す」も実行
期待結果
  • 関連情報の取引先・担当者が変わり、スレッド内の全メールに反映される(取引先詳細の「メール」タブで確認)
  • そのメールから登録した問い合わせの取引先・担当者も変わる
  • 別の取引先の案件への紐付けは外れる(案件のメール履歴から消える)
  • 新しい担当者・取引先が作られ、担当者一覧・取引先一覧に出る
  • 重複するメールアドレスは「既に登録されています。一覧から選んでください」で止まる
  • 「紐付けを外す」後は取引先・担当者が「未登録」になり、担当者・取引先そのものは残る
MB-10
通常
フォーム通知の項目名と送信元の設定
前提MB-06 と同じ送り方で、項目名を「貴社名(必須):」「ご担当者様:」「連絡先メール:」のように標準に無いものにした通知メールを用意。
手順
  1. 設定なしで同期し、担当者一覧を確認
  2. 設定 → 問い合わせフォームの通知メールで、氏名の項目名に「ご担当者様」、メールアドレスの項目名に「連絡先メール」を追加して保存。届いたメールを削除して再同期(または新しい通知メールを送る)
  3. 「通知メールの送信元アドレス」にフォームツール役のアドレスを登録し、項目名が全く合わない本文の通知メールを同期
  4. メールアドレスの形式でない値を送信元アドレスに入れて保存
期待結果
  • 設定なしでは本文を読み取れず、差出人(フォームツール役)が担当者として登録されるか、AI 抽出で問い合わせ者が登録される(どちらになったかメモ)
  • 項目名を追加した後は本文の問い合わせ者が登録される
  • 送信元アドレスを登録すると、読み取れなかった場合でもフォームツール役のアドレスは担当者として登録されず、スレッドの担当者は「未登録」になる
  • 形式違反は「送信元アドレスの形式が正しくありません」で保存できない
MB-08
通常
スレッドと案件の紐付け
前提案件が 1 件以上ある。
手順
  1. スレッド画面の「案件を選択」で案件に紐付ける
  2. 案件詳細でメールが表示されることを確認し、紐付けを外す
期待結果
  • 案件詳細の関連メールにスレッドが出る
  • 外すと消える

§5問い合わせ

メール一覧で選んだメールを問い合わせとして登録し、状態(新規 → 対応中 → 案件化 / 完了)を管理します。同期で自動登録はされません。

IQ-01
必須
メールから問い合わせを登録
手順
  1. メール一覧で受信メールを 2 通選択し「問い合わせに登録」
  2. 同じメールでもう一度登録
  3. 問い合わせ一覧を確認
期待結果
  • 2 件が「新規」で登録され、件名・取引先・担当者・メール本文が表示される
  • 登録済みのメールは重複登録されず、その旨が表示される
  • サイドメニューの「問い合わせ」に新規件数のバッジが出る
IQ-02
必須
状態変更と案件化(アポ取得)
手順
  1. 問い合わせを「対応中」にする
  2. 「アポ取得」で案件化し、案件名などを入力
  3. 案件カンバンを確認
期待結果
  • 状態が順に変わり、案件化すると「案件化」になって案件へのリンクが付く
  • 案件はステージ「アポ取得」に作られ、取引先・担当者が引き継がれる
IQ-03
通常
手動登録と削除
手順
  1. 「追加」で件名なしで登録 → 件名ありで登録
  2. 削除ボタン → 確認ダイアログでキャンセル → 再度削除で確定
期待結果
  • 件名なしは「件名は必須です」
  • キャンセルでは消えず、確定で消える。紐付いていたメールは残る

§6案件と売上

ステージは アポ取得 → 提案書作成中 → 提案済み → 検討中 → 保留 → 成約 / 失注。成約には月次売上の入力が必須です。案件の「行動」タブで電話・メール・訪問などの履歴と期限付き Todo を管理し、期限超過は赤で警告します。行動の種類は設定画面で追加・並び替えでき、期限・アポイント日時・受注予定日は「今日・明日…」のボタンと 2 週間タイルのカレンダーで入力します(過去の日は選べません)。

ステージ確度備考
アポ取得30%問い合わせからの案件化時の初期ステージ
提案書作成中40%
提案済み50%
検討中60%
保留20%
成約100%売上明細(金額と計上月)が 1 件以上必須。金額の合計が案件金額になる
失注0%失注理由を入力
DL-01
必須
案件の作成・編集・カンバン移動
手順
  1. 「追加」で取引先なし・案件名なしで保存
  2. 取引先と案件名、金額、営業担当を入れて保存
  3. カードをドラッグして「提案済み」へ、同じ列内で並べ替え
  4. 詳細でメモを追加・削除
期待結果
  • 取引先と案件名が必須のエラーが出る
  • 移動後に再読み込みしてもステージと並び順が保たれる
  • ダッシュボードの「ステージ別パイプライン」に反映される
DL-02
必須
成約には売上入力が必須
手順
  1. 案件を「成約」へ移動し、売上入力を空のまま確定
  2. 計上月 2 か月分(例: 今月 100,000 / 来月 50,000)を入れて確定
  3. 売上ページとダッシュボードを確認
  4. 成約の案件を「検討中」に戻す
期待結果
  • 空のままは「売上明細を 1 件以上入力してください」で止まる
  • 確定後、案件金額が 150,000 になり成約日が付く
  • 売上ページの該当月に金額が計上され、年間合計が合う
  • 戻すと成約日が消え、売上明細も消える
DL-03
通常
失注と失注理由
手順
  1. 案件を「失注」へ移動し理由を入力
  2. 失注の案件を「提案済み」に戻す
期待結果
  • 詳細に失注理由が表示される
  • 戻すと理由が消える
DL-05
必須
行動の登録・完了・期限超過の警告
前提進行中の案件が 1 件ある。
手順
  1. 案件詳細の「行動」タブで、種類「電話」・内容を入れ、期限を「今日」+「時刻を指定…」で現在より前の時刻(例: 08:00)にして登録(過去の日付は選べないため、当日の過ぎた時刻で期限超過を作る)
  2. 種類「見積書作成」で期限「今日」+「時刻なし(終日)」、種類「電話折り返し依頼」で期限「日付を選ぶ」のタイルから 5 日後を選んで登録
  3. 種類「訪問」で「済んだ行動として記録する」にチェックして登録
  4. 案件一覧(カンバン)とダッシュボードを確認
  5. 期限を過ぎた行動にチェックを付けて完了にし、再度確認
  6. 鉛筆で内容と期限を編集、ゴミ箱で 1 件削除
期待結果
  • 期限を過ぎた行動は赤い背景と「期限超過」バッジ、タブに「超過 1」の赤いバッジ、上部に「期限を過ぎた行動が 1 件あります」の警告
  • 終日の行動は黄色の「今日」で、期限は日付だけ(時刻なし)で表示される。5 日後は「予定」扱い(バッジなし)、済んだ行動は打ち消し線と完了日時で下に並ぶ
  • 並び順は 期限超過 → 今日 → 5 日後 → 完了 の順
  • カンバンのカードに「期限超過 1」「今日 1」、サイドバーの「行動」に赤いバッジ「1」、ダッシュボードの「進行中の案件」に「期限超過の行動 1 件」、「今日やること」に 3 件(期限超過・今日・5 日後)が種類・内容・案件名・取引先付きで並ぶ
  • サイドバーの「行動」ページで、期限超過 / 今日 / それ以降 のグループに分かれて表示され、期限超過の行のチェックを付けると完了になり一覧から消える。「完了済みも表示」で完了分が見える
  • 完了にすると警告とバッジが消え、カンバン・ダッシュボードからも減る
  • 編集・削除が反映される
DL-06
必須
行動の種類の設定(追加・編集・並び替え・削除の制限)
前提DL-05 で種類「電話」を使った行動がある。
手順
  1. 設定 → 「行動の種類」で既定の 6 個(電話・メール・訪問・見積書作成・電話折り返し依頼・その他)を確認
  2. 「オンライン商談」をアイコン「Web 会議」で追加
  3. 上下の矢印で「オンライン商談」を先頭に移動し、ページを再読み込み
  4. 「見積書作成」の名前を「見積提出」に、アイコンを「契約・書類」に変更
  5. 「電話」を削除 → 「オンライン商談」を削除
  6. 同じ名前「メール」で追加、21 個目を追加
  7. 案件詳細の「行動」タブを開き、種類ボタンの並びを確認。新規テナント(会社 B)の設定も確認
期待結果
  • 既定 6 個が最初から入っている(会社 B にも同じ 6 個)
  • 追加した種類がアイコン付きで一覧に出て、並び替えは再読み込み後も保たれる
  • 名前・アイコンの変更は、登録済みの行動の表示(行動タブ・行動一覧・ダッシュボード)にも反映される
  • 使用中の「電話」は「この種類を使っている行動が 1 件あるため削除できません」で止まり、未使用の「オンライン商談」は削除できる。残り 1 個になったときは「最低 1 個必要」で削除できない
  • 同名は「同じ名前の種類があります」、21 個目は上限エラー
  • 行動タブの種類ボタンが設定の並び順どおりで、先頭の種類が最初から選ばれている
DL-07
必須
期限・アポイント日時・受注予定日の入力部品
前提進行中の案件が 1 件ある。PC とスマホ(または幅 400px 程度)の両方で確認。
手順
  1. 行動タブで「明日」を押し、続けて「午後 14:00」を押して登録
  2. 「日付を選ぶ」を押してタイルを開き、‹ › と「今日に戻る」で週を動かし、次の週の平日を選んで「時刻を指定…」で 09:30 を選び登録
  3. 「日付を選ぶ」で祝日(9 月なら 21〜23 日)と土日の表示、今日より前のタイルを押せるかを確認
  4. 日付を選んだあと「時刻なし(終日)」のまま登録し、「クリア」で未設定に戻して期限なしでも登録
  5. 登録済みの行動を鉛筆で開き、期限の初期表示が保存した日時と一致することを確認して別の日に変更
  6. 案件の編集(鉛筆)でアポイント日時を「来週◯曜」+「13:00」、受注予定日を「来月末」にして保存。案件の新規作成でも同じ部品が出ることを確認
期待結果
  • 日付ボタンは 今日・明日・明後日・来週◯曜・1 週間後・日付を選ぶ の 6 個。押すと時刻ボタン(午前中 10:00・午後 14:00・夕方 17:00・時刻なし(終日)・時刻を指定…)が現れ、下に「9月16日(水) 14:00 · 明後日」のように確定内容が出る
  • タイルは 7 列 × 2 段の 14 日分。曜日と日付が大きく、月が変わる日に「◯月」、祝日は赤い「祝」と祝日名。土日祝は薄い背景で選べる。今日より前は薄く押せない。‹ は今日を含む週で無効
  • 選んだ日がボタンに無い日のときは「日付を選ぶ」ボタンがその日付の表示に変わる
  • 「時刻なし(終日)」で登録した行動は一覧で日付だけが表示され、その日のうちは「今日」、翌日になると「期限超過」になる
  • 編集ダイアログの初期表示が保存内容と一致する(日付ボタンに該当する日はそのボタンが選択状態、時刻は該当ボタンまたはプルダウン)
  • アポイント日時には「時刻なし」が無く、時刻ボタンは 10:00・13:00・14:00・16:00。受注予定日は「今月末・来月末・再来月末・日付を選ぶ」で時刻なし。保存後の詳細画面・カンバンのカードに反映される
  • スマホ幅でもタイルが横にはみ出さず、ボタンが折り返して押せる

  2. 成約案件を削除して売上ページを再確認
期待結果
  • 年ごとの月次表と年間合計が切り替わる
  • 案件を削除すると売上も消える

通常

  • 削除時は紐付くデータへの影響が案内され、削除後に案件側の取引先が外れる(または削除が止まる)。挙動をメモに記録
MS-02
必須

前提MB-07 で「リード」を付けた担当者がいる。
手順

  2. 担当者を選択してタグ「顧客」を追加、「リード」を外す
  3. 「CSV ダウンロード」を実行し Excel で開く
期待結果

  • タグの付け外しが即時反映される
  • CSV は絞り込み条件を反映し、文字化けせず(BOM 付き UTF-8)、氏名・会社・メール・タグ列がある
MS-04
必須

前提取引先 X(ドメインあり、案件 1 件・売上あり・担当者 1 名・メールあり)と、同じ会社を指す取引先 Y(ドメインなし、担当者 1 名・問い合わせ 1 件)。
手順
  1. 取引先 Y の詳細で「統合」を押し、X を検索して「「X」に統合する」
  2. X の詳細と、担当者一覧・問い合わせ・案件・売上ページを確認
  3. X の詳細で「統合」を開き、X 自身が候補に出ないことを確認
期待結果
  • 確認文に統合元・統合先の名前と「元に戻せません」が出て、統合後は X の詳細に遷移する
  • Y の担当者・メール・問い合わせが X に移り、Y は一覧から消える
  • X の案件・売上はそのまま。X のドメインなど埋まっている項目は上書きされず、空欄だけ Y の値で埋まる(メモは連結)
  • Y のドメインが X に無かった場合は引き継がれる
MS-05
必須
担当者の統合
前提同じ人を指す担当者 P(メールあり、タグ「リード」、メール 2 通、問い合わせ 1 件)と Q(メールなし、電話あり、タグ「顧客」、案件 1 件の担当)。
手順
  1. 担当者一覧で Q の行の統合アイコン(矢印が合流する形)を押し、P を検索して統合
  2. P の詳細(取引先詳細の担当者タブ)、メール一覧、問い合わせ、案件を確認
  3. 取引先詳細の担当者タブからも同じ操作ができることを確認(別の重複ペアで)
期待結果
  • Q のメール・問い合わせ・案件の担当者が P になり、Q は消える
  • P のタグが「リード」「顧客」の両方になる(重複しない)
  • P の電話が空なら Q の電話で埋まる。P のメールアドレスは変わらない
  • 確認文に、統合元のメールアドレスが残らない旨の注意が出る(統合元にメールがある場合)
MS-06
通常
担当者の所属変更がメール・問い合わせに波及する
前提担当者 R(取引先 X 所属、メール 2 通・問い合わせ 1 件・案件 1 件)。
手順

  2. 取引先 X と Z の詳細の「メール」「問い合わせ」「案件」タブを確認
期待結果
  • R のメールと問い合わせの取引先が Z に変わる(X のタブから消え、Z のタブに出る)
  • 案件は X に残ったまま(案件は取引先に属するため動かさない)
MS-03
通常
タグ設定(既定 6 個、最大 20 個、並び替え)
手順
  1. 設定 → タグで既定の 6 個(リード・セールス・パートナー・顧客・失注・要注意)を確認
  2. 名前と色を変更、新しいタグを追加
  3. 上下の矢印で「要注意」を先頭に移動し、ページを再読み込み
  4. メール一覧のタグ絞り込み・選択時のタグメニュー、担当者一覧のタグ絞り込みを開く
  5. 合計 21 個目を追加
  6. 使用中のタグを削除
期待結果
  • 新規テナントにも既定 6 個が最初から入っている
  • 並び替えは再読み込み後も保たれ、タグの選択肢と絞り込みの並びが設定の順になる
  • 21 個目は上限エラー
  • 削除するとメール・担当者からもそのタグが消える
